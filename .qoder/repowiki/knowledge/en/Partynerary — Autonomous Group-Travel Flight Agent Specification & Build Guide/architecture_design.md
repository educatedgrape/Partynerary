The module is purely documentary — it contains the authoritative specification (`project_scope.md`) that defines the system's five engines (Vibe Matcher, Date Scheduler, Atlas Flight Search, Reconciliation Engine, Repair Loop), the 12-stage orchestrator lifecycle from date consensus through post-order watch, and the `cost_ref` pointer architecture that makes every rendered number dereferenceable into an Atlas response. The phased build guide (`build-guide.md`) maps that spec to concrete implementation phases (transport → probe coverage → vector dataset → retrieval → sweep/scoring → party/consensus → executor gates/re-price → orchestrator → server/UI) with per-phase file inventories and gate commands. `best-practices.md` codifies design principles (dependency graph over lists, re-plan after commitment, reserve-on-commitment/settle-on-payment, ceilings not wallets). Dependency direction is one-way: this module prescribes how `src/`, `probe/`, `tools/`, `web/`, and `tests/` must be structured; nothing in those directories references back here at runtime.
